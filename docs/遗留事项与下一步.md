## 一、gasket（垫片）：两套独立的出图实现

### 1.1 现状：gasket 与另外三个零件不是同一套代码

| | gasket（垫片，老实现） | bracket / lbracket / ybracket（新实现） |
|---|---|---|
| 文件规模 | `s2_drawing.py` 397 行、`s3_render.py` 165 行 | `s2_drawing.py` 250~283 行、`s3_render.py` 208~254 行 |
| 视图 | **4 个**（多一个轴测图 Iso） | 3 个（Top / Front / Right） |
| 比例 | 0.25 / 0.16 / 0.20（缩小） | 2.0（bracket、lbracket）/ 0.8（ybracket） |
| **标注定位** | **按坐标找边 → `References2D` 绑边** | 按半径找圆 / **两点距离 `makeDistanceDim`** |
| 标注函数 | `dia(view, r, cx, cy, …)`、`disty(view, z1, z2, …)`、`rad_neck(...)` | `add_dia(view, r, …)`、`add_disty(view, y1, y2, …)` |
| 垫片专属逻辑 | 凸台顶线 `boss_top_y`、凹颈 `rad_neck`、侧孔轴线 `side_hole_axis_x` | 无 |

**代码证据**

```python
# gasket —— 按 z 值找两条水平边，绑到边上
def disty(view, z1, z2, X, Y, label):
    k1 = find_hline(view, z1)
    k2 = find_hline(view, z2)
    d.Type = "DistanceY"
    d.References2D = [(view, "Edge%d" % k1), (view, "Edge%d" % k2)]

# 另三个 —— 直接算两点距离，不绑边
def add_disty(view, y1, y2, X, Y, label):
    v1 = App.Vector(0, _y(y1), 0); v2 = App.Vector(0, _y(y2), 0)
    d = TechDraw.makeDistanceDim(view, "DistanceY", v1, v2)
```

### 1.2 为什么本轮没纳入 lib

1. **接口套不上**：`lib/drawing_fc.py` 的 `DrawingBuilder.add_disty` 是两点距离，
   gasket 要的是"按 z 找边再绑 `References2D`"。硬套等于给 gasket 重写一套标注逻辑。
2. **它是默认零件**：`pipe.py` 不带 `--part` 就跑它，改坏的影响面最大。
3. 它现在**工作正常**：闭环 pass、视图不出框。收益 < 风险。

### 1.3 ⚠️ 但要注意：gasket 的做法其实更接近项目目标

`README.md` 里写的是：

> 图纸上的每个尺寸都是 FreeCAD 的 `DrawViewDimension`，用 `References2D` 引用投影边。
> 改三维 → `recompute` → 尺寸值自动跟随。

**只有 gasket 完整做到了这点**。另三个里仅 `add_dia` / `add_rad` 绑边，
`add_distx` / `add_disty` 用的是两点距离。

⇒ **将来若要统一，应该以 gasket 的「绑边」方式为基准去改造另外三个，而不是反过来。**

### 1.4 推进方式 —— ①②③ ✅ 全部完成（2026-10-15）

1. ✅ **给 `DrawingBuilder` 增加 gasket 那套方法**（`dia_by_center` / `disty_by_edge` /
   `rad_by_center` + 底层 `find_hline` / `find_vline` / `_bound_dim` / `_circle_at`）
2. ✅ **逐个零件迁移到绑边**，每处都验了「实测值不变 + 像素 0 差异」
3. ✅ **孔心距也绑上了**（见下，思路来自用户提问：「自动生成圆心点，圆心绑圆，再关联圆心」）

**② 的迁移结果**（每一处都跑了 `tools/diff_images.py`，**像素全部 0 差异**）：

| 零件 | 迁了几处 | 迁的是 | 值验证 |
|---|---|---|---|
| **bracket** | 6 | `arm_outer` / `arm_inner`（臂侧面竖直边）、`T_base`（底板上下表面）、`head_h` / `arm_h`（水平边）、`arm_len`（圆头切点↔臂端面竖直边） | 14 项标注**全部一致** |
| **ybracket** | 5 | `wall_t` / `opening` / `base_h` / `arm_t` / `cbore_depth` | 6 项全部一致 |
| gasket | — | 本来就是绑边的 | — |

**③ 孔心距绑定 —— 用户提问引出的关键发现**

② 迁完后剩 3 处 `add_distx`，全是**两孔圆心距**，当时判为「圆心不是投影边，绑不上」。
用户提问：「如果有画圆的话自动生成圆心点、圆心绑圆、再关联圆心，会不会好一点？」

**实测证明这个思路可行，而且比预想的更简单**：

> **圆心在 TechDraw 的投影几何里本身就是一个 Vertex**。HLR 从 3D 投影时把圆心
> 输出为顶点，所以 `References2D = [(view, "VertexN")]` 能直接绑到它，
> 而且因为投影几何每次 recompute 都从 3D 重新生成，顶点**天然随 3D 跟随**。

不需要「自动生成圆心点」——真实圆心已经在投影几何里了，只要找到它的下标。

**决定性实测**（`freecadcmd`，底板两φ9 孔）：

```
pitch=45 → 引用 Vertex6/Vertex9，尺寸值 45.00
把 3D 改成 pitch=60（标注引用一个字没动）
  → Vertex6 自动移到 (-30.000, 0.000)，尺寸值自动变 60.00
```

**下标稳定性**（关键风险点）：模型绕 Z 转 90°、几何完全重排后，
原 `Vertex14/Vertex17` **仍指向同一对孔心** ⇒ 下标稳定，不是巧合。

**实现**（`lib/drawing_fc.py`，新增 3 个方法）：

| 方法 | 作用 |
|---|---|
| `vertex_index_at(view, x, y, tol=1e-4)` | 找投影几何里最接近 (x,y) 的顶点下标 |
| `_center_vertex_indices(view, r, n, pick)` | 按半径找 n 个圆 → 它们圆心对应的顶点下标 |
| `distx_by_centers` / `disty_by_centers` | 孔心距绑顶点（调用方**不写 Vertex 下标**，按半径给） |

调用方按**半径**给参数而不是写下标 —— 几何一变下标就没意义了。

**迁移结果**（每一处都验了实测值 + 像素 0 差异）：

| 零件 | 标签 | 值 | 视图 | 结果 |
|---|---|---|---|---|
| bracket | `P9` 底板 2×φ9 孔心距 | 45 | Front | 值一致，像素 0 |
| lbracket | `pitch` 立板顶 2×φ8 孔心距 | 26 | Right | 值一致，像素 0 |
| ybracket | `ear_pitch` 双耳孔心距 | 116 | Top | 值一致，像素 0 |

⇒ **四个零件的 `add_distx` / `add_disty` 真实调用已全部清零**。
这两个方法现在**零产品依赖**，但按 §〇 纪律 3「删除前必须查依赖 + 刷新基线」，
本轮**暂不删**（留着当过渡期的兜底，以及将来遇到真·无法绑的量时仍需要）。
需要删时跑 `python tools/arch_impact.py --strict` 确认 0 依赖即可。

**① 的实测证据**（lbracket 的 Front/Top 视图，`freecadcmd` 里真跑）：

```
disty_by_edge(Front, y=-19.5, y=+19.5)            → FreeCAD 实算值 38.6574
dia_by_center(Top, r=4.089, cx=22.27, cy=-13.06)  → dia 8.1771 / rad 4.0886
```

关键差别：`add_disty` 传的是**两个坐标点**，值是算出来的；
`disty_by_edge` 传的是**两条边**，FreeCAD 自己从投影边量出 38.6574。
**这才是 README 那句「改三维→尺寸自动跟随」的实质兑现。**

### 1.4之二、顺带修掉的一个工具缺陷（2026-10-15）

`tools/arch_impact.py` 原先把「类的方法集合变了」一律判成 `改签名的符号`，
于是**新增方法也会被 `--strict` 拦成退出码 2**。这与 `MSG.md §〇` 纪律 1
「只增不改」直接矛盾：纪律推荐的正是新增方法，工具却不让过。

已修正为区分三种情况：

| 改动 | 报告归类 | `--strict` |
|---|---|---|
| 新增方法 | `[新增的符号] 无需处理` | 退出码 0 |
| 删除方法 | `[删除方法 X]` | 退出码 2 |
| 改已有方法参数 | `[改参数 X]` | 退出码 2 |

三种都实测过（改完立刻恢复，`git diff` 确认工作区无残留）。

## 二之二、2026-10-15 新增遗留

### 2.1 `s3_render` 下沉后gasket 未跟随

`s3_render` 已下沉到共享层，bracket / lbracket / ybracket 三个零件改用 `draw_spec.py`，
**但 gasket 仍是独立的 165 行 matplotlib 实现**（自有 `ln`/`arrow`/`txt`/`draw_view`，
4 个视图含轴测 Iso）—— 就是§1.1 说的"两套独立出图实现"。

**没跟着降级是刻意的**：gasket 的标注方式（按坐标找边 → 绑 `References2D`）
本来就是§1.3 判定的**项目目标基准**，强行套进 `draw_spec.py` 的
`extent/h/v/extent_y/leader` 五种 kind 反而是倒退。

正确的处理见 §1.4 三段式：先给 `lib/drawing_fc.py` 补绑边方法，
再迁 gasket，最后两套合一。**这一条属于 §1.4 的范围，不在 s3_render 下沉这一刀里。**

### 2.2 几何往返已全通，但仍是「全数值」

`tools/recorder.py` + `tools/ir2build.py` 实测**4 个零件体积差全部 0.0**
（2026-10-15，见下表）。这一轮补齐的能力：

| 补的东西 | 为什么必须 |
|---|---|
| `Plane.offset` 运行时录制 | 源码里的 `-hw` / `x0` 是 s1_build **局部变量**，params 里没有，离线永远求不出值 |
| `Plane * Pos(...)` 静态扫`POS(...)` | 凸台定位；运行时补丁**行不通**（`Plane.__mul__` 自调 → RecursionError，已撤回） |
| `Locations(...)` 录制 | `with Locations((x,y)): Circle(r)` —— **圆心在 Locations 里**，Circle 只带半径，不录就把孔建到原点 |
| 枚举留**成员名** | `mode=Mode.SUBTRACT` 只留 `{"_type":"Mode"}` 无法区分 ADD/SUBTRACT，几何会错 |
| `Polyline` / `CenterArc` 录制 | gasket（8 段圆弧）、ybracket（折线）全靠它们，漏了整组特征丢失 |
| 几何量**不截断** | 4 位小数让圆弧首尾差 ~1e-5，`make_face` 判为不闭合 |
| `both` / `mode` 参数透传 | 漏 `both` 只拉伸单侧（ybracket 背板 58 vs 116） |
| `align` 用枚举名 | 硬编码 CENTER 会让 bracket 底板沿 Y 平移（19822 vs 19313） |

| 零件 | IR 事件 → 特征 | 体积（IR 生成） | 体积（现成 STEP） | 一致 |
|---|---|---|---|---|
| gasket | 13→ 5 | 5409140.094 | 5409140.09 | ✅ |
| bracket | 33 → 10 | 19313.843 | 19313.84 | ✅ |
| lbracket | 26 → 9 | 28969.33 | 28969.33 | ✅ |
| ybracket | 24 → 9 | 1304910.459 | 1304910.46 | ✅ |

**仍存在的缺口**（`ir2build.py` 文档里的已知限制，未变）：
1. 假设所有「加法」特征连续出现在「减法」之前（lbracket 成立；**交错未处理**）
2. 边处理（Fillet/Chamfer）**本版不生成**，打 PLACEHOLDER
3. params 是求值后的数值 → 生成的是**全数值版**脚本，不是 `P.BASE_H` 具名版。
   数值可精确复现几何；「人可读参数名」的 linkage 仍靠 `params.py`
