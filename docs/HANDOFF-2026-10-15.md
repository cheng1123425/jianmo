### 1.4 B：执行+录制抽取器 —— `tools/recorder.py`（本会话新增，未入库）

按技术架构设计 **D7**（实测 AST 丢 5 类信息，录制全对）走"执行+录制"：

```bash
python tools/recorder.py --part parts/lbracket                  # → parts/lbracket/ir.json
python tools/recorder.py --part parts/gasket --out xxx.json
```

**三种注入点**：
1. **模块属性补丁** —— 加载零件脚本前把 `build123d.extrude / fillet / Polygon / Circle /
   Line / Cylinder / Box / Pos` 换成录制代理；脚本自己的 `from build123d import *` 会拿到代理版。
2. **布尔钩子** —— 包 `Compound.__sub__ / __add__`（减/加运算的真正落点），录每次切割/融合。
3. **当前 part 快照** —— 用官方 `Builder._get_context()` 只读取当前 BuildPart 的 `.part`，
   录下**每个特征做完时的中间形状**（bbox / volume / faces / solids）。

❗**关键坑（实测，务必记住）**：
- **`build123d.BuildPart` 和 `BuildSketch` 一点都不能打补丁**——
  - 替换 `BuildPart` → 后续 `extrude` 报 `A face or sketch must be provided`
    （因为 `BuildSketch.__exit__` 向 BuildPart 传 `pending_faces` 的机制被破坏）；
  - 替换 `BuildSketch` 类**或**给它的 `__init__` 打补丁 → `BuildLine` 退出→`make_face`
    报 `No objects to create a hull`。
  - ⇒ **草图平面只能静态扫源码** `BuildSketch(Plane...)` 按组序对齐，标 `resolved:false`
    （`.offset(expr)` 只记原始表达式，不猜）。

**另外两个配对规则**：
- 工具/切割用 **FIFO 队列**（脚本常"先构造全部工具，再统一切割"；"取最近一个"只对第一个生效）；
- `Pos(...) * Cylinder(...)` 的位置在**工具构造时**并入（`Pos` 先求值）。

**lbracket 样板结果**：26 事件 → **9 特征**
（F1 叶形底板 21 点/Plane.XY、F2 立板/Plane.YZ.offset、F3 三角筋/Plane.XZ.offset；
F4-F6 底板孔、F7-F8 立板孔(带 rotation)、F9 窗口 —— 半径/位置/旋转全对）。
每个特征带中间形状统计；`needs_semantic: true`（语义按原则一只能正向标注）；IR 校验 0 问题。

**保真度校验**：录制最终形状 vs 流水线 `s1_build` 真实输出 ——
bbox `56×40×39` 一致、`solids=1` 一致、**体积差 0.03**（纯舍入）✅

## 2. 架构路线定案（本会话核心产出，后续都按这个走）

> 一句话：**IR 是唯一真值源；build123d 是几何引擎；FreeCAD PartDesign 是按需物化的
> 交互面；TechDraw 是出图器；`drawing.anchors` 是把四者缝起来的神经。**

### 2.1 八条纪律

1. **IR 是唯一真值源**（feature graph）——**不是**"IR 同时生成 build123d + FreeCAD"的
   双后端，而是 IR 当中转站，两边都是它的生成物。
2. **build123d = 几何引擎**（生成端唯一几何生产者）。理由：LLM 友好（Pythonic/语料多；
   PartDesign+Sketcher "LLM 几乎必错"）、可三层验证闸门、无头可批量。
   **用户关键纠正**：若不手拖，build123d 反而更容易形成并抽取特征树（脚本即树）。
3. **特征树抽取 = 执行+录制**（D7 已验证）。
4. **FreeCAD PartDesign 树 = 按需物化的交互面**（只在用户要手改时生成；日常生成端不建，
   省双份代价）。
5. **手拖 = 末尾追加**（与 `part = part - hole` 天然对齐）；改参数走 IR 全量重算；
   中段增删先禁止（或只做抑制标记）。
6. **选边存几何谓词，不存 `Edge#12`**（D3：条件查询替代身份引用）。
7. **TechDraw 出图**（`References2D` + `getRawValue`，参数联动已实测）。
8. **编辑流向单向**：FreeCAD 改 → 回写 IR → 重生成 build123d；不回写 FreeCAD
   （免冲掉会话）；若脚本/LLM 直改 IR 则重建两边。

### 2.2 2D↔3D 绑定：分三层，四项决策已定案

| 层 | 绑定什么 | 现状 |
|---|---|---|
| **L1 值级** | 改 3D 参数 → 图上数字自动变 | ✅ 已实现（`References2D`+`getRawValue`） |
| **L2 几何级** | 2D 边 ↔ 3D 边 | 🟡 靠 `s2_drawing` 的 `find_circle`/`find_hline` 按谓词每轮反查 |
| **L3 语义级** | 图上标注 ↔ IR 特征 | ❌ 靠 `drawing.anchors`（差异化核心，未做） |

**四项决策（用户逐条拍板）**：
- ① 锚点放 **IR 特征侧**：`IR.feature → 3D 边 → 2D 投影边`（是"以 3D 边为锚"的超集）；
- ② 绑定**不持久化编号**，存"可重放的几何查询"（`{kind:circle, r≈5, center≈(±45,±30)}`），
  全量重算每轮重新定位 → 抗 TNP；代价是非实时；
- ③ **图纸只读**：不允许在图纸上直接改数字反推模型（与"IR 唯一真值"冲突）；
- ④ **内腔不可见特征当特例放行**（如 ybracket `cbore_depth` 的点距法）：
  代码注释留痕，暂不纳入 anchors 通用机制；出现第二个此类标注或开启隐藏线时再统一。

**`drawing.anchors` 数据结构（已定稿）**：

```yaml
drawing:
  annotation: "4×Φ10"        # 图上印的字（由 impl+params 生成，不手写）
  view: plan                 # top / front / right
  dim_kind: dia              # dia/rad/distX/distY/extentH/extentV
  anchor:
    feature: F2              # L3：指着哪个 IR 特征
    geom: {kind: circle, r: 5.0, center: [±45, ±30]}   # L2：几何查询谓词（不存 Edge#N）
  target_param: dia          # 反查：图上这数对应改 IR 哪个参数
```

**顺带可得的闭环校核升级**：① 绑定存在性（anchor 能否在投影里找到边）；
② 指对性（查到的边实测几何 vs `feature.params` 推出的期望）。
