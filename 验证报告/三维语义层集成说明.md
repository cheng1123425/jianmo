# 三维语义层蒸馏 —— 集成说明

> **日期**：2026-10-14
> **产出**：`jianmo/tools/z2c_distill.py`（蒸馏器）+ `notes/feature_semantics.json`（接入点）
> **状态**：✅ 已接入项目，隔离检查 13/13，闭环回归通过

---

## 1. 做了什么

把 Zero-to-CAD 数据集里的**隐式语义**蒸馏成显式的**三维语义层**，并接入 jianmo 的 `s0_plan`。

```
ADSKAILab/Zero-To-CAD-100k 的 cadquery_file
        │
        │  tools/z2c_distill.py（三路线索）
        ├── ① 参数名语义  hole_diameter / boss_radius / dovetail_depth
        ├── ② 英文注释    "cbore hole through flange side" / "rib on top face"
        └── ③ 操作序列    .union()=加法 / .cut()=减法 / .chamfer()=边处理
        ▼
    feature_semantics.json   ← 三层 IR（语义层 / 结构层 / 操作层）
        │
        ▼
    s0_plan（可选入参 ?notes/feature_semantics.json）
        │
        ▼
    notes/plan.md 的「## 1.1 特征语义（三维语义层）」段
```

---

## 2. 蒸馏器用法

```bash
# 批量：从 parquet 蒸馏
python tools/z2c_distill.py --parquet <file.parquet> [--limit N] [--out DIR]

# 单个：调试一个 cadquery 文件
python tools/z2c_distill.py --code some_part.py
```

产出 `z2c_semantics.jsonl`（每行一个样本的三层 IR）。

**依赖**：仅 `pyarrow`（读 parquet）。**不需要 cadquery**——纯正则 + ast。

    rib_width=15.0, rib_thickness=4.0, rib_height=5.0,

## 5. 修复过的两个实现缺陷（实测发现）

1. **扁平 Measures 漏检**：有些样本的 Measures 没有嵌套（`boss_radius` / `dovetail_depth` 都是顶层标量），
   初版只从**嵌套子特征名**提取，漏掉一多半 → **改为让顶层参数名也参与语义提取**（这正是 97.6% 覆盖的那一路）。
   验证：某燕尾样本从 **0 特征 → 4 特征**。
2. **子串误判 + 特征碎片化**：`dovetail_base` 被 `base` 词根抢成"底板"；`boss_radius`/`boss_height` 被拆成两个"凸台"。
   → **改词边界匹配 + 同父同类型特征合并**。验证：`dovetail_*` 4 参数合并为一个"燕尾"；`boss_*` 合并为一个"凸台"。

## 6. 接入方式（对项目零侵入）

| 接入点 | 改动 | 说明 |
|---|---|---|
| `pipe.py` | s0_plan 的 `in_files` 加一条 `("feature_semantics", "?notes/feature_semantics.json")` | `?` = 可选，文件不存在就跳过 |
| `steps/s0_plan.py` | 读该 role（若有）→ 写进 plan.md 的「1.1 特征语义」段 + 返回 `features` | 缺则整段不出，不影响其它零件 |
| 消约束 | **无** | 仍是标准 mpipe/1 消息，隔离检查 13/13 通过 |

**向后兼容已验证**：bracket / lbracket 无此文件，s0_plan 静默跳过，闭环照常 PASS。

## 7. 与「二维语义层」的分工

| | 二维语义层 | 三维语义层（本次） |
|---|---|---|
| 来源 | `tools/dwg_parser`（读真实图纸） | `tools/z2c_distill`（读 Zero-to-CAD 代码） |
| 产物 | `dwg_semantics.json` | `feature_semantics.json` |
| 内容 | 标注文本 + 接地关系（`Φ150` → 圆） | 特征类型 + 角色（通孔/凸台/燕尾） |
| 消费者 | s5b 尺寸链、s0_plan 读图结论 | s0_plan 特征语义段 |
| 覆盖 | 单个真实零件 | 10 万条合成零件 |

**两者互补**：三维语义层给"**这是什么特征**"的**规模**，二维语义层给"**标注↔特征对应**"的**真实**。
合起来才是 HANDOFF §10 说的完整语义层。

## 8. 局限（诚实记录）

- **只到"特征类型"级**，到不了"用途"级（这孔是安装孔还是销孔）—— 那是设计意图，需 LLM 或人工（HANDOFF §5.9）。
- **55% 样本能出特征**：剩余 45% 多是纯几何构造（无 Measures、无注释），语义信息本身就不存在于数据里。
- **`drawing` 字段恒为 null**：数据集不含图纸，这一环必须来自真实图纸。
- **未在 jianmo 的垫片/支架上端到端验证"用蒸馏语义自动建模"**：本次只验证到"语义层能被 s0_plan 消费"。
  真正的"语义→建模脚本"闭环仍是人工写 `steps/s1_build.py`。
