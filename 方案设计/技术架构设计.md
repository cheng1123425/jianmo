### 一句话架构

> **在 jianmo 的"操作层流水线"前面，插一层"语义层"，并给它配两个进料口（图纸 / 文字）；

```

                 └──────── 本文新增 ────────┘   └──────── 复用现有 ───────────┘
```

## 1. 系统总目标与边界

### 1.1 目标（用户已明确）

| 要求 | 说明 |
|---|---|
| 输出符合国标的工程图 + PDF | 尺寸线 + 箭头 + 引出线 + 尺寸数字，非角落文字 |
| 参数联动 | 改参数重跑，图上所有数字跟着变 |
| 单一数据源 | 一个源 → 跑一次 → 三维/STEP/工程图/PDF/尺寸表全部刷新 |
| 只留一套产物 | 反对新旧并存（曾因两份 PDF 误判改动未生效） |
| 一律附带 PDF | 不能只给 PNG；默认 300dpi、A3 横向、矢量优先 |

### 1.2 系统边界（明确不做什么）

**做**：
- 单一零件的参数化建模与出图（垫片、支架类）
- 从图纸/文字提取语义
- 参数↔标注双向对应

**不做**：
- ❌ 装配体（build123d 0.13.0 无求解器，已实测确认；如需要走"显式定位"路线）
- ❌ 几何→语义的逆向识别（特征识别是几十年的难题，语义不唯一）
- ❌ 生产级制造图纸（公差/粗糙度/材料只做承载，不做工艺判定）
- ❌ 增量重建（走全量重算，理由见 §3.1）

## 2. 核心设计原则（三条铁律）

### 2.1 原则一：语义层只做"正向标注"，绝不做"逆向识别"

**为什么**：从几何反推"这是什么特征"（特征识别）有两个致命问题：
1. 技术上是 CAD 领域几十年未解难题；
2. **语义本身不唯一**——同一个 φ8 圆孔，可以是"安装孔 / 销孔 / 走线孔 / 减重孔"，几何完全一样，含义不同。

**所以**：语义只能**在造数据/输入时正向标注**，不能事后从几何猜。

**落地**：图纸上的标注（`4×Φ8`、`R3`、`C1`）**就是现成的语义标签**——这是选"图纸优先"的根本原因。文字输入时，人在描述里写的语义同理。

### 2.2 原则二：3D 与 2D 的关系是"一对多"，不是函数

**实测证据**：同一个圆柱，四种代码写法体积全为 `9424.7780`、面数全为 3，差异只在位置。

**推论**：
- **正向（代码→几何→投影）是确定函数** ✅ 可靠
- **反向（几何→代码/语义）一对多，不唯一** ❌ 不可靠

**所以**：系统的"真值"永远在**正向**这一侧。校核时比对的是"投影 vs 图纸基准"，**不是**"代码 vs 代码"。

> 这也解释了为什么 Zero-to-CAD 从不用"代码是否匹配"当指标，只用几何 IoU。

### 2.3 原则三：每层只通过"显式契约"通信

**复用 jianmo 的既有做法**：步骤之间只允许通过消息文件传递数据，`guard.py` 静态扫描强制（禁止跨步骤 import、禁止硬编码路径）。

**扩展**：语义层、输入层也纳入同一套消息协议，不允许"隐式共享状态"。

**两个图纸检验步骤（s5b / s6b）在闭环中的位置**：它们与 s6_compare 平级，都挂在
s5_collect 之后、s7_decide 之前——每轮闭环都跑，结论进 `in_data` 汇总给 s7 判定。

### 3.2 为什么这样分层

| 层 | 为什么独立 | 关键取舍 |
|---|---|---|
| **L0 输入层** | 图纸和文字是两种完全不同的解析路径，但**出口必须统一**成同一种 IR | 两个解析器 + 一个统一出口，而不是两套系统 |
| **L1 语义层** | 系统唯一的新增核心，也是**差异化的全部所在** | 三层齐备（缺一层就断链） |
| **L2 投影层** | 把"语义 IR"翻译成 jianmo 能吃的 `params.py` + `dims_spec.py` | **适配器模式**，让新输入接上旧核心，旧核心一行不改 |
| **L3 流水线核心** | 已实测跑通，**不重写** | 只复用，降低风险 |
| **L4 输出层** | 已成熟 | 只复用 |

### 3.3 图纸检验环节：两个隔离步骤（v2.0 新增）

图纸校验回答两个**不同**的问题，必须分开，否则出了偏差查不出是哪边的责任：

| 步骤 | 回答的问题 | 依赖 | 不通过意味着 |
|---|---|---|---|
| **s5b_dimchain** | 图纸本身说得通吗？（Σ各段 = 总尺寸？漏标/重标？） | 只依赖标注集合 + 圆，**不依赖模型** | 图纸错 / 接地错 |
| **s6b_projection** | 三视图之间说得通吗？（长对正/高平齐/宽相等） | 只依赖投影数据 | 图画错了（投影关系违规） |
| s6_compare（原有） | 模型做得对吗？（模型 vs 图纸基准） | 模型 + 基准 | 三维画错 |

**为什么必须隔离**（mpipe/1）：
1. 三个校验各自只通过消息文件通信（`refs` + sha256 校验），互不 import；
2. `s5b` 不依赖模型 → **模型还没建好时就能先验图纸**，图纸错了不必白建一场；
3. 驱动器运行时强制"只有 s8_apply 能改 params.py"——校验步**只读不改**，结论进 `in_data` 交给 s7_decide 判定；
4. `guard.py` 静态扫描保证上述约束（当前 13/13 通过）。

**尺寸链算法**（`tools/dimchain.py`）：
- 线性链：并查集按"接地端点重合"构链 → Σ各段 vs 封闭环 → closure / over_dim / under_dim / asymmetry
- 径向链：每个圆心簇取最外圈圆 → **首末半径 + 相邻圆心距 = 外缘总跨度**（全部换算成 mm）
- 反查接地：标注值与链一致、但接地段量偏了 → 判定"接地位可疑，建议按尺寸链取值"（`fixes.pitch_from_chain`）

**投影原则算法**（`steps/s6b_projection.py`）：长对正（主视/俯视 x 相等）、高平齐（主视/侧视 y 相等）、
宽相等（俯视 y = 侧视 x）、视图齐全、中心共线、图尺相符（视图装得下它的尺寸）、主视高度链闭合。

## 4. 关键技术决策与理由

| # | 决策 | 结论 | 理由（实测/依据） |
|---|---|---|---|
| D1 | 技术路线 | **代码生成式**，非几何生成式 | 要参数化、要出图；几何生成式不可编辑 |
| D2 | 建模语言 | **build123d 0.13.0** | 本机已装、出图链路成熟、闭环已跑通 |
| D3 | 更新机制 | **全量重算**，不做增量 | FreeCAD TechDraw 的 TNP 缺陷致跨重建断链；脚本路线用"条件查询"替代"身份引用"，从根上避开 |
| D4 | 装配体 | **显式定位**，不用约束求解 | build123d 0.13.0 实测无 `Assembly`、无 `solve` |
| D5 | 缓存 | 中间结果可缓存，**仅在"改下游"时生效** | 缓存的是几何（死数据），改上游即全废；边界同 SolidWorks Ctrl+B |
| D6 | 验证 | **三层闸门**：执行/几何/导出 | 含「恰好 1 个连通实体」——实测踩过悬空陷阱 |
| D7 | 步骤提取 | **执行+录制**，非静态 AST | 实测：AST 丢 5 类信息（17步 vs 42条），录制全对 |
| D8 | 语义获取 | **正向标注**，不逆向识别 | 语义不唯一（同孔可多义），逆向是几十年难题 |
| D9 | 真值方向 | **正向（代码→几何）为准** | 反向一对多，不唯一 |
| D10 | 通信 | **消息文件 + 隔离校验** | 复用 jianmo 的 mpipe/1 协议 |
| D11 | 图纸自洽校验 | **尺寸链**（独立步骤 s5b） | Σ各段 = 封闭环是国标基本规则；不依赖模型，图纸错了先发现，不白建 |
| D12 | 图纸规范校验 | **投影原则**（独立步骤 s6b） | 长对正/高平齐/宽相等是图纸语言；与几何精度问题分离，责任可定位 |
| D13 | 图纸语义获取 | **传统 CV 三层分离提取**（dwg_parser） | Drawing-Recode 思路复现：几何层/标注层/接地层分离，AGL 接地的替代实现；VLM 路线不可控（见 §8） |
| D14 | 工程符号识别 | **字形几何分类**，不用 OCR | 实测 tesseract 对 Φ/R 无能为力；改用拓扑特征（孔数=2+竖笔贯穿 → Φ；宽扁 aspect≥0.72 → R） |

### 4.1 关于 D3 的重要澄清（修正 HANDOFF 文档 §3）

HANDOFF 文档 §3 写"FreeCAD TechDraw **无法**保持 2D/3D 同步"——**这个说法偏绝对**。

**事实**：jianmo 项目用 `References2D`（尺寸关联到视图边）+ `getRawValue()` 现场读值，**实现了参数联动**（本次实测：改 dia → 标注自动变）。

**准确表述**：TechDraw 的**拓扑持久命名（TNP）有缺陷**，跨"增量重建"会断链；但在**每次全量重跑**的前提下，关联是成立的。

**所以**：D3（全量重算）不是"因为做不到同步"，而是"用全量重算换取关联的可靠性"。

## 5. 数据模型：语义 IR（系统的心脏）

### 5.1 三层 + 一映射（缺一层就断链）

| 层 | 内容 | 能否自动得到 | 谁消费 |
|---|---|---|---|
| **语义层** `semantic` | 这是什么（底板/安装孔/加强筋） | ❌ **必须标注** | 出图（写 `4×Φ8` 而非 `circle+extrude`）、3D↔2D 对应 |
| **结构层** `structural` | 主体/加法/减法/边处理 | ✅ 可自动（特征块切分） | 组织建模顺序 |
| **操作层** `impl` | rect/extrude/cut… | ✅ 可自动（执行+录制） | 建模脚本 |
| **映射** `drawing` | **标注 ↔ 参数 的对应关系** | ❌ 必须标注 | ★ 参数联动的唯一依据 |

### 5.2 关键洞察：三层可以"逐步降级"

**操作层可以脱离语义层独立工作**——这正是 Zero-to-CAD 达到的程度（它到操作层就停了）。

这意味着两件事：
1. **没有语义层，几何也能跑通** → 所以语义层不是"为了能跑"，是"为了出图和联动"；
2. **渐进式实现是可行的**——先只要操作层（几何能出），再补语义层（图纸能标），最后补映射（参数能联）。

### 5.3 语义字段的最小设计（不追求完美 schema）

**教训**：不要先设计完美 schema（连该有几个字段都不知道）。先跑最小闭环，字段自然浮现。

```yaml
part: 底板4孔
features:
  - id: F1
    semantic:   { type: base_plate, role: 主体, dims: {L:120, W:80, T:12} }
    structural: { kind: 主体 }
    impl:       [rect(120,80), extrude(12)]
    drawing:    null                    # 主体不直接标注

  - id: F2
    semantic:   { type: hole_pattern, pattern: rectangular, count:4,
                  dia:8, role: 安装孔, 位置: 四角 }
    structural: { kind: 减法, target: F1 }
    impl:       [grid_locations(90,60,2,2), circle(4), extrude(-12)]
    drawing:    { annotation: "4×Φ8", view: plan }    # ★ 3D↔2D 对应

  - id: F3
    semantic:   { type: edge_fillet, role: 边处理, R:6 }
    structural: { kind: 边处理, target: F1 }
    impl:       [fillet("|Z", 6)]
    drawing:    { annotation: "R6", view: plan }
```

**`drawing` 那一行就是差异化核心**：有了它，「`dia` 从 8 改成 10 → 图纸上 `4×Φ8` 自动变 `4×Φ10`」才成立。

### 5.4 输入层已落地：dwg_semantics.json（v2.0 新增）

L0 的出口不是抽象 IR，而是一份**具体文件** `notes/dwg_semantics.json`（由 s0b_dwgread 产出，
对应上表 `drawing` 那一行的机器可读形态）。实测结构（法兰盘图纸，6 圆 / 12 标注 / 11 接地）：

```json
{
  "mm_per_px": 0.34012,                    // 半径投票标定（多个圆投票，取支持数最多的比例）
  "scale_method": "circle_vote(支持9/36)",
  "circles": [ {"cx":.., "cy":.., "r_px":.., "r_mm":75.2, "d_mm":150.3}, ... ],
  "dims": [
    {"text":"Φ300", "type":"diameter", "values":[300.0], "box_px":[..], "center_px":[..],
     "grounded":true, "kind":"dia", "measured_mm":302.02, "method":"dia+leader/arc",
     "confidence":0.993, "p1":null, "p2":null},
    {"text":"200", "type":"linear", "grounded":true, "measured_mm":186.38,
     "p1":[789,2768], "p2":[1337,2768], "len_mm":186.38, "confidence":0.932}
  ]
}
```

**三层分离提取**（Drawing-Recode 思路的传统 CV 复现）：

| 层 | 做法 | 实测结果 |
|---|---|---|
| 几何层 | 两级霍夫圆检测 + 圆周覆盖率验证 + 同心圆径向扫描 | 6 个圆全对（含同心簇） |
| 标注层 | 连通域切字 + **字形几何分类**（Φ：孔数=2 且竖笔贯穿；R：宽扁 aspect≥0.72），不用 OCR | 12 条标注全检出，数值全对 |
| 接地层 | 半径投票标定 + 引线追踪 + 圆角相切求解 + **尺寸界线法**（首选）/ 箭头尖法（兜底） | 11/12 接地成功 |

**关键设计——接地的三级判据**（实测踩过三轮坑后定型）：
1. **尺寸界线法**（首选）：尺寸界线垂直于尺寸线、从被测要素引出，位置即尺寸端点。在厚度剖面上，
   界线是**窄尖刺**（沿轴 2~8px），实心箭头是**宽鼓包**（≥10px），尺寸线本身低于阈值——三者被区段宽度干净分开；
2. 箭头尖法（兜底）：界线被遮挡时，取宽鼓包内厚度最小处为尖端；
3. 量尺寸线自身跨度（兜底）：粗但可用。

**残留误差交给尺寸链环节处理**（不再像素级硬抠）：如 `200` 实测 186.38mm、`550` 实测 531.94mm——
由 s5b_dimchain 的 `pitch_vs_dim` 检出（"标注值与链一致但接地段量偏了"）并给出建议值 201.35mm。

| `dims_spec.py` | 尺寸命名规范 | 复用**结构**，内容由 IR 生成 |

### 6.3 接口契约（关键：让新输入接上旧核心）

**核心设计**：L2 投影层是一个**适配器**——把语义 IR 翻译成 jianmo 能吃的东西。

```
IR ──[project/orient]──→ params.py      （jianmo 的唯一数据源）
IR ──[project/dims_map]─→ dims_spec.py  （jianmo 的命名规范）
```

**这样做的价值**：jianmo 的流水线**一行不改**就能接收新输入。这是"复用核心+重写输入"的技术落地方式。

**契约约束**（必须遵守）：
- `params.py`：扁平命名（`R_*`/`D_*`/`H_*`/`BASE_T`），IR 的语义层参数映射到这里
- `dims_spec.py`：每个标注有 `key/cat/solid/label/rel/style/expr` 七个字段（jianmo 既有结构）
- `drawing.annotation` 里出现的每个标注，**必须在 `dims_spec` 有对应条目**——否则联动断链

| 模型投影 vs 图纸基准有差 | s6_compare | 三维画错 |

## 8. 关键难点与应对

| 难点 | 性质 | 应对策略 | 风险 |
|---|---|---|---|
| **图纸视图识别 + 尺寸OCR** | L0 最硬的一环 | ✅ 已落地：传统 CV 三层分离（`dwg_parser`），Φ/R 用字形几何分类代替 OCR；VLM 路线（arXiv 2607.27558 类）作为后续备选，但**不依赖**（不可控、无法给出接地坐标） | 🟢 已降级（简单件可用） |
| **标注↔特征关联** | 3D↔2D 对应的核心 | 靠 `drawing` 字段显式建立，不靠猜；接地层给出 measured_mm + confidence，**接地位可疑的交给尺寸链反查**（不像素级硬抠） | 🟢 已降级 |
| **箭头/界线定位** | 接地层最难的一环 | 三级判据：尺寸界线法（首选，窄尖刺 vs 宽鼓包）→ 箭头尖法 → 尺寸线跨度 | 🟢 已解决（50/50/300/550 全中） |
| **语义层字段设计** | 易陷入"设计完美schema" | 先跑最小闭环，字段自然浮现 | 🟢 低 |
| **投影边→成图的渲染** | 本次最小闭环暴露的真问题 | 复用 jianmo `s3_render.py`（已有视图变换+分层） | 🟢 低 |
| **国标符号完整性** | 粗糙度/形位公差 | 先做基础标注，符号库后续扩充 | 🟡 中 |
| **多零件复用** | 已验证可行 | jianmo 的 `--part` 机制天然支持 | 🟢 低 |
| **图纸错 vs 模型错混淆** | 偏差无法归因 | 三路校验分离：s5b（图纸自洽）/ s6b（投影规范）/ s6_compare（模型精度），全部 mpipe/1 隔离 | 🟢 已解决 |

## 9. 分阶段实施路线

### 阶段一：打通最小闭环（1 个最简单零件）

**目标**：手工走完 ①→⑤，看哪根箭头断。

```
挑 1 张最简单的习题图（一个底板 + 4 个孔）
  → 手工写语义标注（先人工，不写代码）
  → 手工写成 IR
  → 生成 build123d 脚本
  → 出工程图 + PDF
  → 拿原图逐项对照
```

**交付**：能出图的单零件闭环。
**状态**：✅ **本次已实测跑通**（详见 `HANDOFF验证报告.md`）。结论：五箭头全通，3D↔2D 联动成立。

### 阶段二：固化语义层

**目标**：把手工 IR 变成可复用的 schema + builder。

- 定 IR schema（基于阶段一的实践，不空想）
- 实现 `ir_builder`：文字输入 → IR
- 实现 `project/orient` + `project/dims_map`

**交付**：文字输入 → IR → 出图。

### 阶段三：接入图纸解析

**目标**：图纸 → IR。

- `drawing_parser`：视图识别 + 尺寸 OCR + 标定
- 标注↔特征关联
- 人工修正通道

**交付**：图纸输入 → IR → 出图。
**状态**：✅ **v2.0 已落地**（`tools/dwg_parser` + `steps/s0b_dwgread.py`）。实测：6 圆全对、
12 条标注 11 条接地成功；残留误差（200/550）由 s5b_dimchain 的尺寸链反查给出建议值。
注意与初期设想的一处偏差：**符号识别没用 OCR，改用字形几何分类**（tesseract 对 Φ/R 无能为力，见 D14）。

### 阶段三·五：图纸检验环节（v2.0 新增）

**目标**：把"图纸说得通吗"与"模型做得对吗"分开，且检验全部隔离。

- `tools/dimchain.py`：尺寸链算法（并查集构链 + 径向链 + 接地反查）
- `steps/s5b_dimchain.py` / `steps/s6b_projection.py`：两个独立隔离校验步骤
- 注册进 `pipe.py`（13 步），`guard.py` 13/13 通过

**交付**：每轮闭环同时产出「图纸自洽性」与「投影规范性」两份独立结论。
**状态**：✅ **已落地**（实测：原图侧 1 线性链 + 4 径向链 + 2 问题；模型侧 2 问题；投影原则 4 项结论）。

### 阶段四：工程化 + 扩展

- 复用 jianmo `--part` 做多零件
- 符号库扩充（粗糙度、形位公差）
- 视觉反馈回路（Zero-to-CAD 作者明确说没做，因为当时模型识别不稳）

**本轮实测暴露并已修复的三个 bug**：

1. **模型侧假端点导致尺寸链误报**：`_dims_from_drawing` 曾自造 `p1=[0,0], p2=[value,0]`
   假端点，`build_chains` 把全部尺寸并成一条链，closure 误报 Σ=1895≠550。改为按 (view, axis)
   分组的数值闭合（Σ段值 vs 视图跨度），假端点与死代码（bbox）一并删除。
2. **out.data 键名冲突吞掉 s6 的 issues**：s5b/s6b 最初把 `issues` 平铺进 out.data，
   按 `in_data_from` 平铺进 s7 入参时**覆盖** s6_compare 的 issues（字段不兼容，s7 直接
   KeyError，闭环必崩）。改为命名空间隔离（`dimchain` / `projection` 一个键收口），
   s7 显式按键消费。
3. **medianBlur 吃掉 1px 细线**：TechDraw 300dpi 渲染的尺寸线只有 1px 宽（中心黑像素 +
   抗锯齿边 212），`medianBlur(3)` 之后 859 个墨像素只剩 77 个，尺寸线法整体失效。
   去噪改为**连通域面积过滤**（面积 <12px 才丢），细长线完全无害。
